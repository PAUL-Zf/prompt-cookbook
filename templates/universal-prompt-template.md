# 通用 Prompt 模板

> 将方括号中的内容替换为实际信息，删除不适用项后使用。不要把示例占位符当成真实输入。

## 角色与目标
你是一名[与任务直接相关的角色]。
请帮助我完成[具体任务]，用于[使用场景与对象]。最终希望实现[可观察的结果]。

## 材料与背景
- 当前状态：[已经完成什么，遇到什么问题]
- 输入材料：[文件路径、链接、数据、代码或正文]
- 关键背景与领域约束：[必要知识]
- 可用工具与环境：[已知能力；未知则先检查]
- 时效要求：[资料范围、版本或截止日期]

## 范围与权限
- 范围内：[需要完成的内容]
- 范围外：[不需要处理的内容]
- 操作模式：[只读分析 / 允许修改的具体文件与动作；默认只读]
- 必须保留：[兼容性、用户已有改动、安全要求等]
- 外部操作：[提交、推送、发布、发送、采购等是否已授权；默认未授权]
- 资源约束：[时间、成本、依赖、输出长度等]

## 工作方法
1. 检查材料与目标，区分已知事实、假设和未知项。
2. 先完成现有信息支持的工作。非阻塞缺失可注明合理假设继续；影响正确性、范围或授权的关键信息应先澄清。
3. 根据任务复杂度制定必要步骤，简单任务直接处理，不为流程而增加流程。
4. 优先验证影响最大的风险，使用适合任务的工具；不虚构工具、数据或运行结果。
5. 在授权范围内完成工作并检查结果。无法完成的部分明确说明原因和后续所需条件。

## 交付物
- 形式：[对话报告 / 文件 / 代码修改 / 表格等]
- 内容：[必须包含的章节或功能]
- 受众与表达：[语言、专业深度、篇幅]
- 引用要求：[来源链接、文件位置、版本或日期]
- 交付位置：[如需要；未指定时先采用环境约定]

## 验收方式
- [具体、可验证的标准 1]
- [具体、可验证的标准 2]
- [必要边界或异常场景]
- 分开报告已验证、未验证及未通过的内容。
- 重要结论有依据；推断和估算明确标注；结果符合操作范围。

## 最终汇报
先给结果，再简要说明依据、实际完成内容、验证情况和剩余问题。只保留有助于理解与决策的细节，不复述完整工作日志。
