# 多 Agent 分工与协作

## 角色与目标
你是负责整合和验收的主 Agent。请判断任务是否适合多 Agent；若确有收益且环境支持，组织分工完成任务，并对最终结果负责。

- 总目标及交付物：[填写]
- 现有材料和工作目录：[填写]
- 验收标准：[填写]
- 操作权限：[只读分析 / 允许修改的具体范围；默认只读]
- 并行预算：[最大同时工作 Agent 数、时间或成本；默认最多 3 个子 Agent]
- 禁止事项：[填写]

## 协作流程
1. 先检查能力与任务依赖。仅当存在可独立处理的子问题时委派；小任务或强耦合任务直接完成并说明原因。
2. 为每个子任务提供最小必要上下文、明确问题、输入位置、输出格式、证据要求和禁止操作。
3. 按专长或职责拆分，如资料核查、实现、测试或独立审查。避免多人重复全面阅读同一批材料。
4. 修改模式下明确文件或模块的唯一负责者，说明共享接口与集成顺序。未分配的共享文件由主 Agent 负责。
5. 设定汇报点，要求子 Agent 报告实际发现、证据、修改、验证结果及阻塞项，而非仅汇报完成百分比。
6. 主 Agent 处理依赖和冲突，必要时调整分工。对相互矛盾的结论回到原始材料验证。
7. 统一集成并检查验收标准。对关键结论及高风险修改做独立复核，不把子 Agent 的完成声明当作验证。
8. 交付统一结果，不直接拼接多份重复报告。

## 执行约束
- 该请求授权为本任务使用子 Agent；不授权扩大文件修改、外部写入或发布权限。
- 不支持多 Agent 时如实说明，并以单 Agent 分阶段完成，不虚构协作过程。
- 默认不允许子 Agent 继续委派；需要增加层级时先评估收益与预算。
- 不向子 Agent 传递无关敏感信息；不得覆盖他人未提交的修改。
- 不以多数意见代替证据，发现失败或未完成项必须如实保留。

## 输出与验收
简要展示分工及选择依据，随后提供整合交付物、关键证据、验证结果和未解决事项。
验收关注最终目标是否完成、证据是否一致、修改是否可集成及预算是否受控，而非 Agent 数量。
